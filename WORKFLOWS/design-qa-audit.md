# Workflow — Design QA & Audit

## Purpose
Evaluate design frames and screenshots against the brief, design system, layout rules, and acceptance criteria.

## Inputs
- Figma frames, screenshots, prototypes, or rendered pages.
- Approved design brief and page-review standards.
- Responsive targets and component/token references.

## Process
1. Confirm source coverage and review scope.
2. Check hierarchy, alignment, spacing, typography, color, contrast, component consistency, and content density.
3. Check CTA prominence, routing clarity, and interaction affordances.
4. Review responsive layouts and key UI states where evidence exists.
5. Record each issue with location, evidence, impact, severity, and suggested fix.
6. Identify blockers and retest criteria.
7. Produce a QA summary and prioritized remediation plan.

## Severity
- **Critical:** blocks a core journey, creates a serious user-risk, or makes the interface unusable.
- **High:** materially harms task completion, comprehension, or consistency.
- **Medium:** noticeable defect with a viable workaround.
- **Low:** polish issue with limited user impact.

## Outputs
Severity-ranked issue list, evidence register, pass/fail summary, and retest checklist.

## Guardrails
Do not mark an item passed without evidence. Distinguish not-tested from failed. Do not edit design sources unless L3 is approved.
