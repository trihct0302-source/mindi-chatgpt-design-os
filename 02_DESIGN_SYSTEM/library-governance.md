# Skill — Library Governance

## Trigger
Use when proposing changes to shared libraries, naming, ownership, release, or deprecation.

## Required record
Every change records owner, version, date, reason, affected components/pages, migration guidance, and approval.

## Procedure
- Check current ownership and release status.
- Classify change as additive, corrective, breaking, or deprecating.
- Assess downstream impact.
- Define compatibility and migration steps.
- Require QA before replacing a source-of-truth library.
- Archive deprecated items with references; do not silently delete.

## Output
Governance proposal, changelog entry, migration plan, and QA requirements.
